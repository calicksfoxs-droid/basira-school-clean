# بصيرة — تقرير تنفيذ المراحل 1–3

التاريخ: 2026-07-22  
الفرع: `basira-core-platform-v1`

## النطاق المثبت

- منصة واحدة بمدير واحد، ومدرسين مستقلين، وطلاب بحساب موحد لكل طالب.
- الملكية الأساسية: المدرس ← المادة ← المجموعات والوحدات ← الدروس.
- الطالب يرى المواد المنشورة المرتبطة بعضوية نشطة في مجموعته فقط.
- المدرس يدير مواده ومجموعاتها ومحتواها فقط، والمدير يملك رقابة إدارية.
- إعلان رئيسي واحد قابل للتحديث أعلى المادة.
- «رحلة التعلم» إسقاط خفيف لنفس الدروس، وليست نظام بيانات مستقلًا.
- إعدادات عامة للمنصة وتفضيلات شخصية لكل حساب.

## ما تم تنفيذه

1. عقود وأنواع ومخططات تحقق مشتركة للنواة.
2. ترحيل Supabase إضافي ومحافظ على البيانات القديمة، يضيف بنية المواد المستقلة وRLS المطلوب.
3. مخزن عرض محلي حقيقي ومستمر لكل عمليات النواة.
4. مخزن Supabase حقيقي يعتمد جلسة المستخدم وRLS ولا يستخدم مفتاح الخدمة لتجاوز الصلاحيات.
5. إجراءات خادمية لإنشاء المادة والمجموعة والوحدة والدرس وتحديث الإعلان وربط الطالب والإعدادات.
6. معرّف انضمام مستقل عن رمز الدخول: عالي العشوائية، قابل للتدوير، ويُخزن كبصمة وقيمة مقنعة فقط.
7. كشف القيمة الكاملة لمعرّف الانضمام مرة واحدة، مع استجابة `Cache-Control: no-store`.
8. طبقة اختيار موحدة بين مخزن العرض وSupabase.

## تحقق المرحلة

- ESLint: ناجح بلا أخطاء.
- TypeScript: ناجح.
- Vitest: 44/44 ناجحة.
- Build: ناجح، 27 صفحة ثابتة/ديناميكية جرى توليدها وفحصها.
- Playwright: 8/8 ناجحة على سطح المكتب والهاتف.
- التحقق الأمني الثابت: ناجح، 14 ملفًا مطلوبًا و110 ملفات مصدر جرى فحصها.
- ثبت الاختبار أن القيمة الكاملة لمعرّف الانضمام لا تُكتب في قاعدة العرض.

## قيد التحقق الحالي

لم يُشغّل اختبار RLS حي على Supabase محليًا لأن Docker Desktop غير مشغّل وSupabase CLI غير مثبت. لم يتم تشغيل Docker قسرًا حفاظًا على موارد الجهاز. الترحيل مغطى بعقد ثابت واختبارات البناء، لكن تطبيقه على قاعدة PostgreSQL/Supabase نظيفة واختبارات العزل الحية يبقيان ضمن بوابة التحقق الأمني النهائية في المرحلة الخامسة.

## نقطة التوقف الإلزامية

لم تُعدّل واجهة المستخدم في هذه الدفعة. المرحلة الرابعة تبدأ فقط بعد مناقشة اتجاه الواجهة مع صاحب المنتج واعتماد الشاشات والتدفقات، كما طُلب.
